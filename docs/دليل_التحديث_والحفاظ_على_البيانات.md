# دليل التحديث — التطوير مع تحديث البيانات فقط (بلا فقدان)

هذا الدليل يشرح كيف تطوّر التطبيق وتُصدر تحديثات **تُثبَّت فوق النسخة السابقة
وتُحدّث البيانات فقط** (ترحيل)، دون أن يفقد المستخدم ملاحظاته.

القاعدة الذهبية ثلاثية:
1. **وقّع بالمفتاح نفسه دائمًا** (`alaoufi-release.jks` من نسختك الاحتياطية عبر
   `android/key.properties`) → التحديث يُثبَّت فوق القديم بلا فقدان بيانات.
2. **ارفع رقم النسخة** في `pubspec.yaml` → أندرويد/Play يعدّه تحديثًا.
3. **رحّل قاعدة البيانات بالإضافة فقط** (`_onUpgrade`) → لا تُفقد البيانات.

> 🔑 مفتاح التوقيع أُزيل من المستودع لأمان، لكنه **لم يتغيّر**. طالما تبني بالمفتاح
> نفسه (الموجود في نسختك الاحتياطية/الحزمة المرسَلة) تبقى كل الملاحظات عند التحديث.
> **لو بنيت بمفتاح مختلف أو debug** فلن يُثبَّت فوق القديم (يضطر المستخدم للحذف
> وفقدان البيانات) — لذلك احتفظ بالمفتاح ولا تغيّره أبدًا.

---

## 1) رقم النسخة (Versioning)

في `pubspec.yaml`:
```yaml
version: 1.8.0+49
#        └┬──┘ └┬┘
#    versionName  versionCode  (name+code)
```
- **النسخة الحالية:** `1.8.0+49`.
- **`versionName`** (`1.8.0`): يراه المستخدم. ارفعه حسب حجم التغيير
  (تصحيح `1.8.1` / ميزة `1.9.0` / كبير `2.0.0`).
- **`versionCode`** (`49`): **يجب أن يزيد في كل إصدار** (رقم صحيح متصاعد). Google
  Play يرفض أي حزمة برقم بناء ≤ آخر رقم مرفوع.

مثال للإصدار التالي: `1.8.1+50` ثم `1.9.0+51` … إلخ.

> رقم البناء يُقرأ في أندرويد من `flutter.versionCode` (انظر `build.gradle.kts`)،
> فيكفي رفع `+NN` في `pubspec.yaml`.

## 2) ترحيل قاعدة البيانات (البيانات تُحدَّث ولا تُمحى)

الملف: `lib/data/database/app_database.dart`. آليتان:

- **`_onCreate`** يعمل مرّة واحدة على جهاز **جديد** (تثبيت أوّل) — ينشئ كل الجداول.
- **`_onUpgrade`** يعمل على جهاز **فيه بيانات** عند زيادة `_dbVersion` — ينفّذ فرق
  المخطّط فقط (إضافة عمود/جدول) **مع الإبقاء على كل الصفوف**.

**إصدار المخطّط الحاليّ:** `_dbVersion = 21`.

### وصفة إضافة تغيير جديد على القاعدة (مثال: عمود جديد في v22)

1. **ارفع الإصدار** في `app_database.dart`:
   ```dart
   static const _dbVersion = 22; // كان 21
   ```

2. **أضف العمود في `_onCreate`** (كي يحصل عليه المستخدم الجديد مباشرة). مثال داخل
   جدول `notes`:
   ```dart
   // ... بقية الأعمدة
   pinned_color INTEGER,        // ← العمود الجديد
   ```

3. **أضف فرع ترقية في `_onUpgrade`** (كي يحصل عليه المستخدم القديم **بلا فقدان**):
   ```dart
   if (oldVersion < 22) {
     await db.execute('ALTER TABLE notes ADD COLUMN pinned_color INTEGER');
   }
   ```

4. **حدّث النموذج** في `lib/data/models/note.dart`: أضف الحقل إلى الصنف و`toMap()`
   و`fromMap()` و`copyWith()`.

5. **حدّث ملف المخطّط المرجعيّ** `docs/schema.sql` (أضف العمود) وأعد توليد
   `docs/schema-reference.db`.

هذا كل شيء — عند التحديث سيرى المستخدم القديم بياناته سليمة مع العمود الجديد فارغًا
(القيمة الافتراضية)، والمستخدم الجديد يبدأ بالمخطّط الكامل.

### قواعد السلامة (مهمّة)
- ✅ **أضِف فقط**: `ALTER TABLE … ADD COLUMN` أو `CREATE TABLE IF NOT EXISTS`.
- ✅ لأعمدة `NOT NULL` أعطِ **قيمة افتراضية** (`DEFAULT`) وإلا يفشل الترحيل على صفوف
  موجودة.
- ❌ **لا تعدّل** فرع `_onUpgrade` قديمًا نُشر سابقًا — أضف فرعًا جديدًا فقط.
- ❌ **لا تحذف/تعيد تسمية** عمودًا في تحديث إنتاجيّ (SQLite محدود؛ إن اضطررت، اتبع
  نمط «جدول جديد + نسخ + إسقاط» كما في ترقية v8 داخل الملف).
- ❌ **لا تغيّر `_onCreate`** بشكل يخالف نتيجة سلسلة `_onUpgrade` — يجب أن ينتهي
  الاثنان إلى نفس المخطّط النهائيّ.

> ملاحظة: التطبيق يرحّل تلقائيًّا أيضًا من قاعدة نصّية قديمة إلى مشفّرة بأمان (مع
> تحقّق من عدد الصفوف) — لا يلزمك التدخّل.

### ما لا يمرّ عبر قاعدة البيانات
تُحفظ خارج القاعدة (فلا تحتاج ترحيلًا): إعداد مساعد الذكاء (تخزين آمن)، وحالة
الاشتراك/التجربة، وتفضيلات الواجهة وترتيب الأدوات (`SharedPreferences`).

## 3) خطوات إصدار تحديث (Checklist)

```bash
# 1) طوّر التغييرات + (إن لمست القاعدة) اتبع وصفة §2
# 2) ارفع رقم النسخة في pubspec.yaml (مثال 1.8.1+50)
# 3) تحقّق
flutter analyze          # بلا أخطاء
flutter test             # كل الاختبارات تنجح

# 4) ابنِ الحزمة (نفس المفتاح تلقائيًّا)
#    خارج المتجر:
flutter build apk --release
#    Google Play (اشتراكات):
flutter build appbundle --release --dart-define=STORE_BILLING=true
#    مع تفعيل الذكاء للجميع:
#      أضِف --dart-define=AI_ENDPOINT=… --dart-define=AI_PROXY_SECRET=…

# 5) وزّع (APK مباشر) أو ارفع الـ AAB إلى Play Console
```

### لماذا تبقى البيانات؟
- **نفس التوقيع** ⇒ أندرويد يعدّه تحديثًا لا تثبيتًا جديدًا ⇒ لا يمسح بيانات التطبيق.
- **ملف القاعدة نفسه** يبقى مكانه؛ يفتحه التطبيق ويشغّل `_onUpgrade` فقط للفرق.
- **المفتاح نفسه للقاعدة** محفوظ في التخزين الآمن ⇒ يفكّ التشفير كالمعتاد.

نتيجةً: يفتح المستخدم النسخة الجديدة فيجد كل ملاحظاته وإعداداته كما هي، مع الميزات
الجديدة فقط.

## 4) أسلوب البناء لكل نوع نسخة (مرجع سريع)

| النسخة | الأمر |
|---|---|
| خارج المتجر (تفعيل UNI3) | `flutter build apk --release` |
| Google Play (اشتراكات + تجربة ١٠ أيام) | `flutter build appbundle --release --dart-define=STORE_BILLING=true` |
| تفعيل الذكاء للجميع | أضِف `--dart-define=AI_ENDPOINT=… --dart-define=AI_PROXY_SECRET=…` |
| APK لجهاز حديث فقط (أصغر) | أضِف `--target-platform android-arm64` |

راجع `docs/دليل_المطور_الشامل.md` للتفاصيل الكاملة، و`docs/المفاتيح_والأسرار.md`
لبيانات المفاتيح.
